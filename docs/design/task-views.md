# 一覧 / ボード / ガントの設計

## Status

Living（3つの表示は実装済み。ここは「なぜこの形か」と「次に何を直すか」を持つ）

## この文書の役割

3つの表示（一覧・ボード・タイムライン）は同じデータを別の問いに答えるために並べ替えたものである。
どれをどう作るかの判断は[ADR 0025](../adr/0025-kanban-board-view.md)・
[0026](../adr/0026-timeline-not-a-gantt-chart.md)・[0029](../adr/0029-task-links-and-an-editable-gantt.md)に
散っているので、**3つを横に並べて見たときの設計**をここに置く。

## 3つは同じ問いに答えていない

| 表示 | 答える問い | 主役の軸 |
|---|---|---|
| 一覧 | 何があるか。何が遅れているか | 並び順（作成 / 期限 / 開始 / 優先度） |
| ボード | 作業がどこで止まっているか | ステータス |
| タイムライン | いつやるのか。空いているのはいつか | カレンダー |

**同じ機能を3つに複製しない**という原則がここから出る。ボードにステータスの絞り込みが無いのは、
列そのものがそれだからである（[ADR 0025](../adr/0025-kanban-board-view.md)）。

## 調べたことと、それが指した欠陥

外部の一般則を確認したうえで、現状と突き合わせた。**参考にした内容は末尾に列挙する。**

### 1. 走査されることを前提にする → 期限切れが見えていなかった

「ほとんどの利用者はページを読まずに走査する」というNielsen Norman Groupの調査、
そしてAsanaが**期限超過の日付を赤で出す**という実例。

**現状の欠陥**: 期限が過去でも来月でも**まったく同じ見た目**だった。
つまり「遅れているか」を知るには、利用者が全行の日付を今日と比べる必要があった。
走査する人はそれをしない。

**直したこと**: `dueState()` を1つ作り、一覧・ボード・ガントで同じ語彙を使う。
期限切れは色 + 記号 + 左の縦線。**完了したタスクは対象外**——
終わったタスクが遅れていたのは履歴であって、赤くすると完了一覧が警告で埋まる。
色だけでは伝わらないので、ラベルにも「期限切れ」と入れる。

### 2. 重要な情報は同じ位置に置く → メタ情報が行ごとに動いていた

**現状の欠陥**: タイトルの直後にメタ情報が回り込んでいたので、
担当者の位置が行ごとに違い、**列として下に目を走らせることができなかった**。

**直したこと**: 右側に「ステータス → 担当 → 開始 → 期限 → 優先度」の固定順で置く。
狭い画面では外側から落とす（担当は`sm`、開始日は`md`）。

### 3. カードは1枚に1つの仕事、列にはWIPの感覚を → 列が青天井に伸びていた

**現状の欠陥**: 1つの列にカードが増えると**ページごと縦に伸び**、他の列が画面外に出る。
ボードの価値は全列を同時に見られることなので、これは価値そのものを潰していた。

**直したこと**: 列の中だけをスクロールさせる。列見出しに件数に加えて**期限切れ件数**を出す。

### 4. 粒度は問いによって違う → 四半期が letterbox でしか見られなかった

**現状の欠陥**: 1列=1日固定。3か月は2000px を超え、横スクロールでしか読めない。

**直したこと**: 日 / 週の切り替え。週は「特定の火曜日を指せない」代わりに全体が収まる。
どちらかが正しいのではなく、**問いが違う**。

**ズームはURLに入れない。** 表示形式（`view`）は「何を見ているか」なのでURLにあるが、
拡大率は「今どう見ているか」で、リンクを渡された相手に押し付けるものではない。

## 次に直すべきこと

観測可能な条件で書く（[service-readiness-map](./service-readiness-map.md)の規約に合わせる）。

| 項目 | なぜ | 着手条件 |
|---|---|---|
| 一覧のグルーピング | 絞り込みは「他を消す」。担当や期限で束ねて全部見たい | 1プロジェクトが50件を超えたら |
| ボードのドロップ位置表示 | 今は列が光るだけで、どこに入るか分からない | 列内の並び順を持ったら |
| 依存の矢印 | `blocks` はデータにあるが線が無い | 1プロジェクトで`blocks`が5本を超えたら |
| キーボード操作 | ボードもガントもポインタ前提 | 支援技術の利用報告が来たら、または公開前に |
| 仮想スクロール | 100件で切っている（[ADR 0025](../adr/0025-kanban-board-view.md)） | 上限を上げたくなったら |
