# 0029. タスク間の関係を持たせ、ガントチャート上で日程を編集できるようにする（0026の一部を覆す）

## Status

Accepted（[ADR 0026](./0026-timeline-not-a-gantt-chart.md)のうち
**「読み取り専用にする」判断のみを覆す**。「本格的なガントを作らない」判断は依然有効）

## Context

[ADR 0026](./0026-timeline-not-a-gantt-chart.md)はガントを作らない理由を表にして、
**「このデータには存在しない概念」**を並べていた。その1行目が
「依存関係の矢印 ← タスク間の先行/後続 ← 無い」である。

また同ADRは、帯のドラッグによる日程変更を明確に断っていた:

> 帯をドラッグして日程を変える機能は作らない。**ピクセルを日付に戻す**ことになり、
> 1日ずれれば利用者が触っていない期限が動く。

**この2つが今回の対象**である。前者は「無いから作れない」であって「作るべきでない」ではなく、
後者は反論可能な形で書かれていたので、正面から答える。

## Decision

### 階層は列、関係は表

タスクの親は**高々1つ**なので `todos.parentId` という列で表す。
これをリンク行で表現すると**「親が2つ」が表現可能になり**、
スキーマのどこにも書かれていない規則をコードで守ることになる。

`todo_links` は本当に多対多のもの——`related`（対称）と `blocks`（有向）——だけを持つ。
`related` は**1行しか書かない**。両方向を書けば、食い違いうる2行になる。

### 循環は制約にできないので、クエリで拒む

SQLiteに「自分の祖先ではない」を表す手段が無い。再帰CTEで親をたどって拒否する。
**深さに上限を置いた**のは、既に循環が存在してしまった場合に
**それを防ごうとしているリクエストが止まらなくなる**のを避けるため。
防具は、防ごうとしている壊れ方の中でも動く必要がある。

### 外部キーが存在しか検査しないことを、また踏んだ

`parentId` を他人のタスクに向ける操作が**成功していた**。テストが書かれた瞬間に落ちた。
外部キーは**存在**を検査するのであって**所有**ではない——
[ADR 0022](./0022-share-links-cached-in-kv.md)で共有リンクが同じ穴を通ったのと同型である。

越境そのものに加えて、**成功可否から他人のidの存在が漏れる**。
所有スコープ済みの `find` を通し、見えないidは「無い」と答える。

### 自己参照する外部キーは、削除の順序を変える

`todos.parentId` は `todos` を指す。SQLiteは外部キーを**行ごとに**検査するので、
親を子より先に消す削除は失敗する。保持期限のパージ・退会・テストのリセットの
**3経路すべてで、列を作ったコミットの中で**先に切り離すようにした。

### ガント上の編集 —— 0026の反論への答え

反論は「ピクセルを日付に戻すのは危険」だった。答えは**軸が固定グリッドであること**である。
1列がちょうど1日なので、変換は整数の除算で、丸め方を間違える余地が無い。

そのうえで:

- 計算は `applyDrag()` という純粋関数に閉じ込め、**単体でテストしてある**
  （月境界、後方移動、片側だけ日付があるタスク、反転の防止、0日ドラッグ）。
- ドラッグ中は**結果の日付を帯に表示する**。書き込みが不意打ちにならない。
- 帯は**反転できない**。CHECK制約が拒むので、落とした後に失敗を知るより、
  そもそもできない方がよい。
- **0列のドラッグは書き込まない。** `updatedAt` を汚し、
  [ADR 0017](./0017-realtime-with-durable-objects.md)のチャンネル経由で
  全タブに無意味な再取得を配ることになる。
- ドラッグは**唯一の手段ではない**。詳細フォームが同じ日付を編集する——
  [ADR 0025](./0025-kanban-board-view.md)でボードに対して置いたのと同じ原則で、
  ポインタを持たない人が締め出されないため。

### 追記: 軸はカレンダーであって、作業の外接矩形ではない

当初の軸は**タスクの範囲ぴったり**だった。結果、空のプロジェクトは1列、
タスク2つのプロジェクトは日付を動かすたびに縮尺が変わる。
そして何より、**空いている月が「描かれていないので見えない」**。

最小幅を約3か月にし、今日の少し手前から始めるようにした。
これは表示の都合ではなく意味の問題で、**計画は「まだ何も無い期間」に対して立てる**。

月に加えて**日付の行**を出し、週末と今日を縦帯で示す。
帯は行ごとにセルを置くのではなく**1枚のレイヤー**で描く——
90列×100行は9000要素で、背景が1度言えば済むことを言うには多すぎる。

### 追記: ドラッグ中はゴーストを出す

元の帯を薄くしてその場に残し、**着地点をゴーストで重ねる**。
帯そのものを動かすと「どこへ」は分かるが**「どこから」が消える**。
日付も添える——長方形は「だいたいいつ」までしか答えず、
日程の議論は正確な日について起きる。

## Consequences

### 得たもの

- タスクの親子と、`blocks` / `related` の関係。
- ガント上での日程変更（移動と伸縮）。
- 循環の拒否と、越境する親指定の拒否。

### 残っている穴

- **依存関係の矢印は描いていない。** データは持ったが、帯の間に線を引いていない。
  `blocks` は詳細フォームで読めるだけである。
- **`blocks` がスケジュールを拘束しない。** 「先行タスクの期限より前に始められない」は
  検査していない。クリティカルパスも無い。
- **一覧のインデントは1段だけ。** より深い階層はデータにあるが描かない。
- **横スクロールが今日に寄らない。** 軸は今日を含むが、開いた瞬間の
  スクロール位置は左端で、先の予定を見るにはスクロールが要る。
- **粒度は1日固定。** 3か月を見ると横に長い。週や月に丸める切り替えは無い。
- **ドラッグはタッチで未検証。** pointer eventsを使っているので原理的には動くが、測っていない。
- **キーボードで帯を動かせない。** 詳細フォームで編集できるので締め出しではないが、
  ガント上での操作はポインタ限定である。
- **ドラッグ中は他のタブに何も伝わらない。** 落とした時点で初めて配信される。
