# 0028. 表示名を変更可能にし、Todoに担当者を持たせる

## Status

Accepted

## Context

`user.name` はサインアップ時に受け取ったきり**変更できなかった**。
[ADR 0027](./0027-comments-and-append-only-history.md)でコメントと変更履歴を入れて以来、
この値は**他人に見える唯一の名前**になったので、誤字を直すのにアカウント削除が要るのは筋が通らない。

もう一方の「誰が割り当てられているか」は、この時点で**表現手段が2つとも欠けていた**:

1. `authorId` / `actorId` は保存されているのに、**画面はidも名前も出していなかった**。
2. 「担当者」という概念自体が無かった。[ADR 0026](./0026-timeline-not-a-gantt-chart.md)は
   ガントを作らない理由の1つとして、まさにこれを挙げていた。

## Decision

### 名前の変更はBetter Authのエンドポイントを通す

`user` テーブルはライブラリの持ち物なので、自前のハンドラで書かない。
`authClient.updateUser({ name })` がそのまま使える（実測で確認）。

**メールアドレスは読み取り専用のまま。** 変更は同一性の変更であり、
新しいアドレスの所有証明が要る。証明する手段（メール送信）が無い
（[ADR 0013](./0013-better-auth.md)）ので、変えられるように見せない。

### 名前はSQLで解決する。「サインイン中の人」で代用しない

コメントと履歴の一覧は `user` を join して名前を持って返す。
**今日はどちらも同じ人**なので、クライアント側でセッションの名前を使っても同じ結果になる。
それをやらなかったのは、[ADR 0027](./0027-comments-and-append-only-history.md)で
`authorId` を保存した理由と同じ——**偶然一致しているだけの規則は、
一致しなくなった日に静かに壊れる**。joinは今も正しく、そのときも正しい。

### 担当者は `todos.assigneeId`。プロジェクトの所有者から導出しない

「このリストを持っているのは誰か」と「この作業をやるのは誰か」は別の問いで、
1人しかいない間だけ答えが一致する。

**候補は今日ちょうど1人**なので、この列は単体ではほとんど無意味である。
それでも入れたのは:

- [ADR 0026](./0026-timeline-not-a-gantt-chart.md)が「ガントに必要だが存在しない」と名指ししていた項目であること。
- 協働は、**割り当て先を持てるようになってからでないと誰も招待できない**こと。

`ALTER TABLE ... ADD assigneeId text REFERENCES user(id)` は**行があるテーブルで通ることを実測した**。
[ADR 0011](./0011-expand-contract-migrations.md)が記録している失敗する形は
`NOT NULL DEFAULT` と `REFERENCES` の組み合わせで、しかも**空なら通ってしまう**ため、
安全な形かどうかは populated なテーブルで確かめないと分からない。

### 候補一覧はクライアントに問い合わせさせる

`GET /api/projects/:projectId/assignees` は今日1行しか返さない。
「あなた自身です」とクライアントに書かなかったのは、
**その日が来たときに探して直す場所を作らない**ため。

### 未割り当ては `null` のまま表現できる

Selectはnullを持てないので、UI側にセンチネル値を1つ置いた。
これが無いと**割り当てられるが解除できない**という罠になる。

`assigneeId` に一致する候補がいない場合は「不明なユーザー」と表示する。
**「名前が分からない誰か」と「誰もいない」は別の事実**なので、前者を後者に丸めない。

### 割り当ての変更は履歴に残る

`TRACKED_FIELDS` に `assigneeId` を加えた。担当が移ったことは、
期限が動いたことと同じかそれ以上に「あとから聞かれる」種類の変更である。

## Consequences

### 得たもの

- 表示名を直せるようになり、コメントと履歴が誰のものか読めるようになった。
- 担当者の欄ができ、一覧・ボード・タイムラインの3表示すべてに出る。
- 名前の変更が**1タスクも書き換えずに**全画面へ反映される（idを保存しているため）。

### 残っている穴

- **候補はまだ1人。** 「割り当て」が本当に意味を持つのは、
  1つのProjectに複数人が届くようになってから（組織テナンシーはCLAUDE.mdのNot Yet）。
- **ボードもタイムラインも担当者で絞り込めない。** 「自分の担当だけ」は書けない。
  候補が1人の間は無意味なので、意味が出てから足す。
- **アバターが無い。** `user.image` は未使用のまま。
- **担当者が退会したタスクの扱いが未定義。** 退会時は本人のデータごと消えるので今は起きないが、
  他人のプロジェクトに割り当てられる世界では、外部キーがどちらの削除も拒む。
