# 一覧 / ボード / ガント / 概要

1つのプロジェクトのタスクを、4通りに並べる。URLの `view` パラメータで切り替わる
（`/projects/$projectId?view=board`）。

## 4つは同じ問いに答えていない

| 表示 | 答える問い | 並びの軸 |
|---|---|---|
| **概要** | このプロジェクトは今どうなっているか | 集計 |
| **一覧** | 何が残っているか | 任意（作成順・開始日・期限日・優先度） |
| **ボード** | 仕事はどこで詰まっているか | ステータス |
| **ガント** | いつ何が起きるか | 時間 |

**同じデータの見た目違いではない。** どれかで足りるなら他は要らない、という関係ではなく、
それぞれ別の問いのための道具である。

## 表示の切り替えはURLに置く

**絞り込み・並び替え・表示の種類は、すべてsearch paramsに持つ。** コンポーネントのstateにしない。

- リンクで共有でき、リロードでも残る
- `loaderDeps` 経由でloaderが再実行されるので、**SQL側で絞れる**
  （クライアントが取得済みの行を隠すのではなく）

スキーマは `.default()` で「無い場合」を、`.catch()` で「あるが不正な場合」を吸収する
——後者は手でURLを書き換えたときに出る。

**プロジェクトを移るときはsearch paramsを引き継がない。** 絞り込みは離れる側の
プロジェクトのもので、持ち込むと移った先で黙って行が消える。
表示の切り替えは逆に引き継ぐ——同じプロジェクトの中だから。

## 走査されることを前提にする

人は読まずに走査する。**算術が要る事実は、誰も気付かない事実である。**

- **期限は状態として出す。** 期限切れ・本日・まもなく・この先を、色と文言で区別する
  （`src/features/todos/due.ts`）。日付だけを並べると、読者が毎行を今日と比べることになる。
- **完了したタスクに期限の警告は出さない。** 遅れて終わったものは履歴であって、
  完了一覧を赤で埋めても誰の役にも立たない。
- **同じ事実を同じ位置に置く。** 行の右側は常に「ステータス・担当者・開始日・期限日・優先度」
  の順。列として揃うから走査できる。
- **ラベルはタイトルの下、日付の隣ではない。** ラベルは「そのタスクが何であるか」で、
  右側は「どこまで進んでいるか」。混ぜると両方読みにくくなる。

## ボード

列がステータスそのものなので、**一覧のステータス絞り込みは出さない**——
2つあると画面上で食い違う。

ドラッグで列を移すと `status` が変わる。カードは1枚に1つの仕事を表し、
期限切れだけが左端に色の帯を持つ。**すべての状態を目立たせると、何も目立たない。**

## ガント

タスクが存在しない期間も含めて、**あらかじめ3ヶ月程度の幅を描く**。
バーがある範囲だけを描くと、「まだ何も置かれていない」ことが見えない。

- **暦日の計算はUTCで閉じる。** `new Date(y, m, d)` と `toLocaleDateString` を使わない——
  ローカル変換はグリニッジより西の利用者にだけ日付を1日ずらし、**作った側には見えない**。
  レイアウトは `src/features/todos/timeline.ts` の純関数で、`today` も引数で受け取る。
- **月だけでなく日付の目盛りを出し、日/週の粒度を切り替えられる。** 粒度は問いによって違う——
  「今週どうなっているか」と「四半期でどう並ぶか」を同じ目盛りでは読めない。
- **ドラッグ中はゴーストを出す。** どこから動かそうとしているのかが見えないと、
  離すまで結果が分からない。
- **バー全体をドラッグすると期間を保ったまま移動し、端を掴むとその端だけが動く。**
- 日付を持たないタスクは軸に載せられないので、**別に一覧として出す**——黙って落とさない。

## 概要

進捗・ステータス別の件数・期限切れ・まもなく期限・担当者ごとの残件・ラベル別の件数。

**別のクエリにしない。** 数字はすべて他の表示と同じ行から導く。そうしないと
**同じプロジェクトについて要約と一覧が食い違う**瞬間ができる。代償は
「読み込んだ範囲の集計」になることで、これは画面に書く。

`src/features/todos/overview.ts` の純関数で、`today` も引数。同じ行からは常に同じ要約が出る。

**絞り込みは出さない。** 絞り込んだ部分集合の要約は、誰も訊いていない質問への答えである。

## ボードとガントと概要は1ページ分だけ読む

どれも「load more」を持たないので、`WHOLE_VIEW_LIMIT` 件で止まる。
**画面にそう書く**——黙って切ると、無いものが無いのか、読み込まれていないだけなのかが
区別できない。

## タスクの追加は詳細フォームだけ

タイトルだけの入力欄は置かない。**計画に使うタスクがタイトルだけで済むことは稀**で、
速い入口を用意すると、他の項目が存在しないことを画面が教えることになる。

同じ理由で、プロジェクトの作成もダイアログで、名前・キー・説明・色・期間を一度に訊く。
