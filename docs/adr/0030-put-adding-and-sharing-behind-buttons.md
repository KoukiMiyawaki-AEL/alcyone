# 0030. タスク追加と共有をボタンの後ろに置く（0025の「速い経路」を覆す）

## Status

Accepted（[ADR 0025](./0025-kanban-board-view.md)のうち
**「追加は2経路にする」判断のみを覆す**。ボード表示に関する判断は有効）

## Context

プロジェクト画面の上部を、**常設のカードが2枚**占めていた。

1. 「Add a task」——タイトル1行だけの入力欄。
2. 「共有リンク」——発行/コピー/解除のカード。

どちらもタスク一覧を下へ押しやっていた。画面を開く目的は**ほぼ常にタスクを見ること**なのに、
最初に見えるのはタスクではなかった。

## Decision

### 追加はボタン1つ。タイトルだけの経路は消す

[ADR 0025](./0025-kanban-board-view.md)は速い経路を残す理由をこう書いていた:

> ほとんどのタスクは1行で、**その多数派にダイアログを課すのは、少数派のために税を取ること**になる。

**前提が間違っていた。** このリストが扱うのは、状態・担当・開始日・期限・親子・関連を持つタスクである。
1行で完結するタスクは多数派ではなく、速い経路が作っていたのは
**あとで開いて埋め直すことになるタスク**だった。税を取っていたのはむしろこちらである。

「タスクを追加」を押すとフォームが開く。**経路は1つ**で、
[ADR 0024](./0024-todo-status-instead-of-completed.md)で作成と編集を同じフォームにした利点が
そのまま効く——項目も検証も1箇所のままである。

### 共有はヘッダーのボタンの後ろへ

共有は**一度決めたら当分変わらない**種類の設定で、プロジェクトを開くたびに
その状態を読ませる理由が無い。ボタンにして、開けば同じ操作ができるようにした。

**状態はボタン自身に出す**（「共有」／「共有中」）。
公開されているかどうかは、ダイアログを開かないと分からないでよい情報ではない。

### 空状態の文言も直した

「上のフォームから追加してください」と書いてあった。**そのフォームはもう無い**。
消した機能を指し続ける案内は、無いより悪い。

## Consequences

### 得たもの

- 画面を開いた最初に見えるのがタスクになった。
- 追加の経路が1つになり、作られるタスクが最初から埋まっている。
- 共有状態がヘッダーで分かる。

### 失ったもの / 残っている穴

- **1行のタスクを素早く積む操作は無くなった。** 買い物リストのような使い方には
  以前より手数が増える。この判断は「このリストが計画に使われる」という前提に依存していて、
  用途が変われば元に戻す理由になる。
- **キーボードショートカットが無い。** ボタンまでTabで到達する必要がある。
- **共有ダイアログは1プロジェクトにつき1つの設定しか持たない**（[ADR 0022](./0022-share-links-cached-in-kv.md)のまま）。
