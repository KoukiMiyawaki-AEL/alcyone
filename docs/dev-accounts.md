# ローカル開発用のアカウント

```bash
pnpm dev                # 別のターミナルで起動しておく
pnpm run seed:accounts
```

| 権限 | メールアドレス | パスワード |
|---|---|---|
| オーナー | `owner@alcyone.test` | `alcyone-dev-password` |
| 管理者 | `admin@alcyone.test` | 同上 |
| ユーザー | `member@alcyone.test` | 同上 |

`ALCYONE_DEV_PASSWORD` で変えられる。**秘密ではない。** これらは自分の
マシンの、捨てるためのデータベースにしか存在しない。秘密として扱うと、
サインインしたいときに誰も見つけられなくなるだけである。

一般ユーザーも作るのは、**全部できる人だけで画面を見ていると権限のバグが隠れる**ため。
「管理者にだけ見えるはずのもの」は、見えない側のアカウントでしか確認できない。

なお `member@alcyone.test` は**プロジェクトを作れない**（[ADR 0039](./adr/0039-creating-a-project-is-an-operational-act.md)）。
参加者として追加されたプロジェクトで働く側の見え方を確かめるためのアカウントである。

何度実行してもよい。既にあるアカウントはそのまま、権限は毎回そろえ直す。

## なぜ権限だけDBに直接書くのか

アカウントの作成はサインアップのエンドポイントを通す —— Better Auth が自前の
パラメータでハッシュするので、INSERTで作った行は**誰もサインインできないアカウント**になる。

権限の付与だけは `wrangler d1 execute --local` で直接書く。
権限を渡せるのは既に権限を持っている人だけ（[ADR 0034](./adr/0034-three-account-roles-and-a-screen-that-creates-them.md)）で、
**シード用のスクリプトには名乗る相手がいない**。付与しかせず降格はしないので、
迂回している規則（最後のオーナーは降ろせない）を破ることはできない。
localhost 以外のURLに対しては実行を拒否する。

## 既存のデータベースにオーナーがいない場合

`role` 列は migration 0018 で `DEFAULT 'member'` として入り、当時は変更する手段が無かった。
そのため **0018 と 0019 の間に作られたデータベースには、アカウントはあるがオーナーがいない**。
そして権限を渡せるのはオーナーだけなので、その状態からは自力で戻れない
（ブートストラップは `user` が空のときしか動かない）。

migration 0021 が、オーナーがいなければ**最初に作られたアカウント**を昇格させる。
`pnpm run db:migrate:local` を実行すれば適用される。
