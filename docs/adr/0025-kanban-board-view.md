# 0025. Todoをボード表示でも見せ、追加時から詳細を設定できるようにする

## Status

Accepted

## Context

[ADR 0024](./0024-todo-status-instead-of-completed.md)で `status` を入れた結果、
**同じデータを別の並べ方で見る意味が初めて生まれた**。真偽値のときは
「終わったもの/終わっていないもの」しか無く、列にする価値が無かった。

同時に、追加の導線に穴が残っていた。詳細ダイアログは**既存のTodoにしか開けず**、
新規作成はタイトル1行のみ。**期限を持つタスクは、書き留めるその瞬間に期限も分かっている**ことが多く、
「まず作って後で入れる」は期限が永久に設定されない経路である。

## Decision

### 追加は2経路にする。速い方を潰さない

タイトルを打ってEnterはそのまま残す。ほとんどのタスクは1行で、
**その多数派にダイアログを課すのは、少数派のために税を取ること**になる。

そのうえで「詳細」ボタンを置き、**打ちかけのタイトルを持ったまま**同じダイアログを開く。
打ち直しが要るなら誰も使わない。

作成と編集は**同じフォーム**である。項目も検証も2箇所に書かない。
`TodoEditor` が `{ mode: "create", title }` か `{ mode: "edit", todo }` を運ぶ。

### ボードはURLに置く（`view=board`）

別ルートにしない。**絞り込んだボードへのリンクも、このプロジェクトのタスクへのリンク**である。
[ADR 0004](./0004-router-loader-over-query.md)以来の「一覧の状態はURL」と同じ理由で、
共有でき、リロードで残り、loaderが再実行される。

**ボードのときは `status=all` で取得する。** 列そのものがステータスの分類なので、
1つに絞ると3列が空になる。一覧側のステータスフィルタはボードでは隠す——
**2つのフィルタが画面上で矛盾しうる**状態を作らないため。

### ドラッグは唯一の経路にしない

HTML5のdrag and dropは**キーボードから一切到達できない**。
ドラッグを唯一の移動手段にすると、ボードはキーボード利用者にとって「見えるが触れないもの」になる。

各カードに移動先ボタンを置いた。**2つの経路を持つ方が、ドラッグを支援技術対応にするより安い**——
後者はdndライブラリの追加と、その独自のARIA問題を引き受けることになる。
テストが押さえているのは**キーボード経路の方**で、そちらが全員に効く必要があるからである。

同じ列への drop は書き込みにしない。何も変わらない更新は `updatedAt` を汚し、
[ADR 0017](./0017-realtime-with-durable-objects.md)のチャンネル経由で
**全タブに無意味な再取得を配る**。

### ボードは上限を明示する

ページネーション（[ADR ページング](./0011-expand-contract-migrations.md)ではなくキーセット実装）は
1ページずつだが、ボードに「もっと読む」は無い。100件で切り、
**切ったことを画面に書く**。黙って省略するボードは、
「作業がどこにあるか見る」という目的そのものを裏切る。

## Consequences

### 得たもの

- `status` が初めて画面上の構造になった。
- 追加時に期限・開始日・メモを設定できるようになった。
- 表示形式が共有可能なURLになった。

### 残っている穴

- **ガントチャートは未着手。** 検討結果は[ADR 0026](./0026-defer-gantt-chart.md)。
- **列内の並び順を持たない。** ボード内でカードを上下に並べ替えられない。
  順序を持つには `position` 列と、同時更新の扱い（マップ3-3の「同時更新」）が要る。
- **ドラッグはタッチで動かない。** HTML5 drag and dropはモバイルSafariで発火しない。
  移動先ボタンがあるので操作不能ではないが、ドラッグはデスクトップ限定の便宜である。
- **100件を超えるとボードは全体を映さない。** 上限は測って決めた値ではない。
