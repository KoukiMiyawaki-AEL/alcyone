# ドキュメント規約

このディレクトリは、コードやコミットログには残らない「何を作っていてなぜか」「なぜそうしたか」「外部から見た仕様は何か」を記録する場所。

## 何がどこにあるか

| 場所 | 役割 | 更新頻度 |
|---|---|---|
| [`CLAUDE.md`](../CLAUDE.md)（リポジトリ直下） | 「今どう書くか」の運用ルール。コンポーネント規約、デザイントークン、よく使うコマンドなど、Claude Codeが日々参照する現在形の規約 | コード規約が変わるたびに直接書き換える |
| [`docs/design/`](./design/) | 「何を作っていて、なぜその形にしたか」を機能・サブシステム単位で説明する**生きたドキュメント** | 実装が進むにつれて書き換えてよい |
| [`docs/adr/`](./adr/) | 「なぜそうしたか」の決定履歴（Architecture Decision Records）。design docの中で「これは覆されると困る」という個々の決定を切り出したもの | 追記のみ。既存のADRは編集せず、覆す場合は新しいADRを足す |
| [`docs/api/`](./api/) | コードベースの外部仕様（API等）の記録 | 実装が変わったら追従して更新 |
| [`docs/pii.md`](./pii.md) | 保持している個人情報と、その消し方の棚卸し | スキーマが変わったら追従して更新 |
| [`docs/deploy.md`](./deploy.md) | 本番デプロイの手順と、本番でしか確かめられないことの一覧。**まだ実施していない** | デプロイしたら結果を追記 |

## CLAUDE.md / design doc / ADRの使い分け

- **CLAUDE.md** は「今この瞬間、コードをどう書くべきか」を答える。過去の経緯は書かない。
- **design doc**（[`docs/design/`](./design/)）は「何を作っていて、なぜその形にしたか」を機能・サブシステム全体のスケールで答える、決定前から書き始めてよい生きた文書。
- **ADR**（[`docs/adr/`](./adr/)）は「なぜ今のやり方になったか、他に何を検討して何を却下したか」を、1つの決定に絞って答える不変の記録。design docの中の「これは後から覆されると困る」部分だけをADRとして切り出し、design docからリンクする。

CLAUDE.mdの記述と実態が矛盾するようになったら、CLAUDE.mdを更新した上で、変更の理由を新しいADRとして残す。

## 新しい大きな設計判断をしたとき

コード規約レベルの細かい変更ではなく、技術選定・アーキテクチャ・スコープに関わる判断（例: ライブラリの採用/見送り、データフローの方針、後回しにする機能の明記）をしたときは、CLAUDE.mdをいきなり書き換えるのではなく、まず以下のいずれかを行う。

- 機能・サブシステム全体の設計を考えている段階 → [`docs/design/`](./design/) にdesign docを書く（[`docs/design/README.md`](./design/README.md)参照）
- 個別の決定を記録したい段階 → [`docs/adr/`](./adr/) にADRを追加する（[`docs/adr/README.md`](./adr/README.md)参照）

CLAUDE.mdの更新が必要な場合はその後で行う。
