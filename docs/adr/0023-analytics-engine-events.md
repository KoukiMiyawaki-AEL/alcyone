# 0023. 数えるための出来事をAnalytics Engineに書く

## Status

Accepted

## Context

[ADR 0022](./0022-share-links-cached-in-kv.md)の「残っている穴」に
**「閲覧数を数えていない。誰がいつ開いたか分からない。Analytics Engineの領域」**と書いた。
その穴を埋める。

ログとの違いをはっきりさせておく必要がある。両方あるが、答えられる問いが違う:

| | ログ（`console.log` の構造化JSON） | Analytics Engine |
|---|---|---|
| 単位 | **1リクエストを読む** | **多数を数える** |
| 保持 | 短い。しかもサンプリングされる | 時系列として問い合わせられる |
| 問い | 「このエラーは何が起きたのか」 | 「いつから増えたのか」 |

「あの共有リンクは何回開かれたか」「KVのキャッシュは実際に効いているのか」は、
**grepでは答えられない**。ログはサンプリングされるので、数えると嘘になる。

## Decision

**`src/worker/analytics.ts` に、イベントの形を1箇所で固定する。**

### 直せないのは「形」だけなので、そこにテストを置く

Analytics Engineのデータセットは**追記専用でバージョンが無い**。
`blobs[1]` は永久に `blob2` として保存される。つまり:

**位置を入れ替えたり使い回したりすると、過去のデータに対する全てのクエリが静かに壊れる。**
古い行は古い意味のまま残り、**データ自身は何も教えてくれない**。

だからモジュールを1つに絞り、位置をコメントで固定し、
`test/worker/analytics.test.ts` が**過剰に見えるほど厳密に**位置を検査している。
そう見えるのが正しい。ここは後から直せない唯一の部分である。

### 読み戻せないので、境界でテストする

読み取りはCloudflareのSQL APIとアカウントトークンで行う。つまり
**Workerからも、テストからも、書いたものを読み返せない**。

なので偽のdatasetでイベントを受け止め、**書こうとした内容**を検査する。
「実際に届いたか」は検証できないが、**届いたときに正しい形であること**は検証できる。
できないことを、できたことにしない。

### 記録するのは2つだけ

- **`share_view`** — index はトークン、`outcome` が `hit` / `miss` / `not_found`。
  `hit` と `miss` を分けたのが要点で、**これが無いとKVが効いているか分からない**。
  `not_found` を数えるのは、**トークンを総当たりされている姿がそこに出る**から。
- **`server_error`** — index はパス。有用な問いは「どのエンドポイントが壊れているか」で、
  リクエストIDをindexにすると**カーディナリティがトラフィックと同じで、何もグループ化しない**。
  IDはblobに置き、1行からログ行へ辿れるようにする。

### 閲覧者を識別しない

IPもUser-Agentもuser idも書かない。これは**読まれた回数を数える機能**であって、
**誰が何を読んだかの記録**は義務の異なる別の機能である。
テストが不在を直接検査している（[ADR 0011](./0011-expand-contract-migrations.md)の
ログ方針、マップ3-7のPII棚卸しと同じ姿勢）。

### 撃ちっぱなしにする

`writeDataPoint` は値を返さず、リクエストを失敗させられない。
**数えることが、数えられている処理の邪魔をしてはいけない。**

### 書き込みは、呼び出し元を絶対に壊せない形にする

これは実装中にテストが見つけた。`recordServerError` は `app.onError` の中で走る。
**そこで例外を投げると行き場が無い**——Honoの最後の砦が、今まさに投げたものになる。

しかも引き金は「bindingが無い」で十分であり、**それはエラーハンドラが扱っている状況そのもの**である。
不完全なenvを渡したテストが落ちて分かった。

`safeWrite()` で包み、bindingが無くても書き込みが失敗しても黙って諦める。
撃ちっぱなしの形が含意していた規則と同じ:
**数えることが、数えられている処理の邪魔をしてはいけない。**

### indexの96バイト切り詰めは自前でやる

プラットフォームが黙って切るので、**値を選ぶ場所で**切る。
そうしないと「2つの別物が同じindexに落ちて1つに見える」という、
クエリを書いてから気づく類の壊れ方をする。

## Consequences

### 得たもの

- 共有リンクの閲覧数と、**KVキャッシュのヒット率**が測れるようになった（本番で）。
- エラーの発生率が時系列として残る（マップ3-6の可観測性を一段埋める）。
- イベントスキーマが1箇所にあり、テストで固定されている。

### 検証できていないこと

- **1件も読み戻していない。** ローカルのminiflareで `writeDataPoint` は例外を出さないが、
  **保存もしない**。SQL APIを叩くにはアカウントトークンが要り、
  [ADR 0003](./0003-d1-local-only.md)の制約下では試せない。
- **UIに数字を出していない。** 出すにはWorkerからSQL APIをHTTPで叩き、
  アカウントトークンをsecretとして持つ必要がある。**「WorkerがCloudflareのREST APIを叩く」は
  普通は避けるべき形**で、ここでは例外的に唯一の手段になる。やるなら別のADRで判断する。
- **サンプリング率を検討していない。** Analytics Engineは高頻度だとサンプリングし、
  `_sample_interval` を掛けて数える必要がある。トラフィックが無いので判断材料が無い。
- **アラートが無い。** `server_error` が増えても誰にも通知されない。
