# 0033. プロジェクトを「文脈」として扱う（サイドバーの項目から外し、ヘッダーとダッシュボードへ）

## Status

Accepted（[ADR 0032](./0032-inviting-by-email-and-bootstrapping-the-admin.md)が
サイドバーに足したプロジェクト一覧を、置き場所ごと差し替える）

## Context

[ADR 0032](./0032-inviting-by-email-and-bootstrapping-the-admin.md)は
「サイドバーにプロジェクトを選ぶ手段が無い」という欠落を、
**サイドバーにプロジェクトの一覧を足す**ことで塞いだ。これは間違いだった。

サイドバーの残りの項目——一覧・ボード・タイムライン・設定——は
**「このプロジェクトで何ができるか」**を並べている。そこにプロジェクト自身を並べると、
「どのプロジェクトか」と「そのプロジェクトで何をするか」が**同じ階層に見える**。
実際には前者が後者の前提であり、階層が1つ上にある。

しかも一覧が伸びる。プロジェクトが30個ある人のサイドバーは、
機能が5つとプロジェクトが30個で、**機能の側が見えなくなる**。

## Decision

### プロジェクトの選択はヘッダーに置く

現在のプロジェクト名を出すボタンと、切り替えのメニュー。
アプリ名の隣、つまり**画面全体のスコープを示す位置**に置く。

サイドバーは「今いるプロジェクトで何ができるか」だけを持つ。
プロジェクトが開かれていないときは、その節ごと消える——
**何も選ばれていないときに表示の切り替えを出すのは、無いものの見え方を変えるという申し出**になる。

プロジェクト間の移動は search params を引き継がない。絞り込みは離れる側のもので、
持ち込むと移った先で黙って行が消える。表示の切り替え（一覧/ボード/タイムライン）は逆に
引き継ぐ——同じプロジェクトの中だから。

### `/` はダッシュボードにする

名前を並べるだけの一覧では、**開くまで何も分からない**。
プロジェクトごとに、タスク総数・完了数・期限切れ・本日期限を出す。

**1文で集計する。** 一覧を引いてからプロジェクトごとに数えると、
行数ぶんの往復が要るうえ、**名前を読んだ時刻と件数を読んだ時刻がずれる**。

```sql
select p.*, count(t.id), sum(case when ... end), ...
  from projects p
  left join todos t on t."projectId" = p.id and t."deletedAt" is null
 where p.id in (<accessibleProjectIds>) and p."deletedAt" is null
 group by p.id
```

**`deletedAt IS NULL` は JOIN 側に置く。** WHERE に置くと外部結合が内部結合に戻り、
**タスクが1つも無いプロジェクトが消える**——ダッシュボードが最も出すべき相手がそれである。

**ページングしない。** 最初のページだけ出して「概要」と呼ぶのは、全部出すより悪い。
コストは到達できるプロジェクト数に比例する読み取りで、readiness map の 3-4 に記録済み。

**空のプロジェクトは0%と表示しない。** 0で止まったバーは失敗に見える。
空のプロジェクトは失敗していない、始まっていない。

### 「マイタスク」を足す

プロジェクトを横断して、自分に割り当てられた未完了のタスクを1画面に集める。

タスク管理ツールに要るのに無かったのは、**「自分は今日何をするのか」に答える場所**だった。
担当者も期限も優先度も既にあったが、それらは常に**1つのプロジェクトの中でしか**見えなかった。

- 期限で束ねる（期限切れ / 今日 / まもなく / この先 / 期限なし）。
- **プロジェクト名を行に付ける。** 横断の一覧で名前だけ並べると、置き場所の分からない
  タイトルの山になる。SQLのJOINで取る——行ごとに引き直さない。
- **`dueAt IS NULL` は最後に置く。** SQLiteのNULLは昇順で先頭に来るが、
  この画面で期限の無いタスクは**最も急がないもの**であって最も急ぐものではない。
- 完了したものは出さない。「自分に何が乗っているか」の答えに、終わったものは含まれない。

## Consequences

### 得たもの

- サイドバーの項目数がプロジェクト数に依存しなくなった。
- プロジェクトを開かずに、どれが遅れているかが分かる。
- 「今日やること」を、プロジェクトを1つずつ開かずに読めるようになった。

### 残っている穴

- **ダッシュボードのカードは進捗しか出さない。** 直近の更新や、誰が何を持っているかは無い。
- **マイタスクはそこから編集できない。** 開くと、そのプロジェクトの一覧に飛ぶだけ。
- **「担当者が自分」以外の切り口が無い。** 自分が作ったもの、自分がコメントしたもの、
  といった軸は無い。
- **ダッシュボードの集計はページングしない。** 到達できるプロジェクトが増えるほど重くなる。

### テストで気付いたこと

Playwright の `getByRole(..., { name })` は**部分一致**なので、
「ボード」が「ダッシュボード」にも当たるようになった。既に一度踏んでいる罠を、
ラベルを増やしたことで再発させた形になる（`exact: true` で解決）。

サインアップのヘルパーが**レスポンスを見ずに画面だけを見ていた**ため、
拒否されたサインアップが「Projectsの見出しが出ない」としてしか報告されず、
原因の切り分けを何度も誤らせた。レスポンスを直接確認するようにした。
